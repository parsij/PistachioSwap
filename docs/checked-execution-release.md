# Checked Gas Assist account release

This follows [Gas-Assist PR128](https://github.com/parsij/Gas-Assist/pull/128) and [PistachioSwap PR229](https://github.com/parsij/PistachioSwap/pull/229). Reviewed heads were a76878c23f2c3bb199f0ac86e6d19fca10332119 and 14a8aee9c5f826bffda5b957748f79598bf77dbe. The detailed security/migration report is `docs/checked-execution-release-2026-10-23.md` in Gas-Assist. No production features, wallets, deployments or broadcasts were activated by these changes.

Gas Assist now requires a checked EIP-7702 account. Canonical Simple7702Account propagates EVM reverts but ignores false ERC-20 return values. The checked account preserves the user's caller identity, original five/eight-call ABI and source-batch rollback while verifying token returns, exact fee debit/receipt, exact approvals and final zero allowances. A helper cannot approve on behalf of the user and is not used. Actual EntryPoint v0.8.0 execution is tested in Gas-Assist's isolated Solidity suite; provider/source bridge fixtures remain local and do not prove live routing.

The browser pins reviewed checked-account runtime hash `0x122a35372b4884388a452276a33f33c635b4b79a1d0ffb5c646307211a9c3a68` (4465 bytes). Backend-supplied hashes cannot select an arbitrary replacement runtime. Browser verification checks EntryPoint/delegate/Paymaster code, account version and Paymaster immutable bindings before signing. The wallet's build pin is `VITE_CHECKED_7702_ACCOUNT_ADDRESS_<chainId>`; the existing shared `VITE_SIMPLE_7702_ACCOUNT_ADDRESS` can instead be set to the new verified address. Existing delegate changes are blocked with `PAYMASTER_DELEGATION_MIGRATION_REQUIRED`; a separate explicit migration is required. This does not silently change existing EIP-7702 delegation or broaden passkey scope.

Deployment requires new checked delegate instances, new instances of the existing Paymaster implementation (its delegate is immutable), and fixed refill contracts. Keep activation disabled until source/runtime hashes, constructor settings, router/spender authority, actual Bundler simulation and gas caps are verified for each chosen chain. Apply backend SQL0027 before API startup. Drain/reconcile old pending intents under the old deployment before switching configuration. An ambiguous broadcast remains pending, with no blind retry. No fees, treasury, thresholds or refund policy were changed; unused quoted service fees are not automatically refunded. Cross-chain destination settlement remains separate.

## Release gate and reproduced failures

`pnpm exec vitest run src --maxWorkers=2 --pool=forks` passes **1443 tests in 169 files**, without skips or unhandled errors. It now runs as a required PR workflow step. Public API tests separately pass **547 tests in 60 files**. API typechecking, lint and production build pass; lint/build still report existing warnings.

The earlier `fatal library error, lookup self` report was a host procps/PID-namespace error: it reproduced in standalone ps. Saved Vitest output completed with failures; it was not a Vitest runtime abort. No error hiding or failing-test skips were introduced.

Portfolio history had an application subscription defect, fixed through useSyncExternalStore and stable snapshots. Wallet-history fixtures now supply the successful decoded UserOperation evidence required by the classifier. Wallet integration fixtures explicitly choose BNB or provide priced holdings under the newer Ethereum default, supply complete classification evidence, isolate pending module state, and mock the actual configuration hook. CSS assertions retain exact expectations while using filesystem paths and current visual requirements. Architecture limits remain intact through composition/helper extraction. The static swap shell includes its heading/footer; shortened repeated landing copy retains fee/refund/risk disclosures.

These local tests do not demonstrate real external-wallet app/extension acceptance, funded canaries, production execution, or safety for tokens that lie about balances/allowances. No deployment approval follows solely from passing tests.
